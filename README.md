# Go Learn — путь от повторения до Middle за 8 недель

Локальная платформа для изучения Go: теория, практика с автопроверкой, задачи LeetCode, карточки для собеседования и итоговый проект. Все материалы вшиты в приложение — работает без интернета (интернет нужен только для синхронизации с LeetCode).

## Запуск

Требуется Go 1.23+ (проверено на 1.25).

```bash
cd GOLANG
go run .
```

Открой **http://127.0.0.1:8088** — и начинай с кнопки «Начать». Флаги:

```bash
go run . -addr 127.0.0.1:9000     # другой порт (только localhost)
go run . -data ~/golearn.json     # где хранить прогресс (по умолчанию ./progress.json)
go run . -dev                     # читать content/ и web/ с диска: правки материалов видны без пересборки
go build -o golearn . && ./golearn   # собрать один бинарь (контент вшит через go:embed)
```

## Что внутри

| Раздел | Содержимое |
|---|---|
| **Путь** | 8 недель × 5 уроков (≈ 2 часа в день), прогресс, серия дней, «Продолжить» |
| **Теория** | 40 подробных уроков; примеры с кнопкой ▶ — правь и запускай прямо в тексте |
| **Практика** | 69 заданий с автопроверкой через `go test`; подсказки, просмотр тестов, эталонные решения |
| **LeetCode** | 2–8 тематических задач в каждом уроке, автоотметка принятых решений по нику |
| **Карточки** | 93 вопроса для собеседования (знаю / не знаю, очередь повторений) |
| **Шпаргалка** | Команды, синтаксис, шаблоны, ловушки |
| **Чек-лист middle** | Матрица навыков с привязкой к урокам |

### Программа

1. **Основы**: инструменты, типы, управление потоком, функции, слайсы и map
2. **Типы и абстракции**: строки, структуры, интерфейсы, ошибки, дженерики
3. **Конкурентность**: горутины, каналы, sync, context, паттерны
4. **Stdlib и инструменты**: io, JSON/time, тестирование, slog/regexp/heap, модули
5. **Бэкенд I**: net/http, REST, клиент и graceful shutdown, SQL, архитектура
6. **Бэкенд II и внутренности**: безопасность, инфраструктура, память/GC, планировщик, профилирование
7. **Алгоритмы**: хэши, окно, бинарный поиск, списки/кучи, деревья/графы, backtracking/DP
8. **Собеседование и проект**: system design, вопросы по языку и конкурентности, сервис «shrink», экзамен

## Как работать

1. **Теория** (30–40 мин): читай и запускай примеры, меняй код и смотри, что происходит.
2. **Практика** (45–60 мин): пиши решение в редакторе, `Ctrl/⌘ + Enter` — проверка. Прогресс и черновики сохраняются.
3. **LeetCode** (20–30 мин): решай на leetcode.com **на Go**; принятые решения подхватятся по нику.
4. Нажми «Завершить урок», повтори 5–10 карточек.

## Синхронизация с LeetCode

LeetCode не даёт внешним приложениям писать в ваш аккаунт, поэтому прогресс хранится у них (там вы решаете и отправляете решение), а платформа **читает публичный профиль** (GraphQL `recentAcSubmissionList`) и отмечает принятые задачи — сразу при нажатии «Синхронизировать» и автоматически раз в 3 минуты, пока платформа запущена.

Ограничения: публично отдаются только последние ~20–50 принятых решений — синхронизируйся чаще, чем решаешь 20 задач. Любую задачу можно отметить вручную. Задачи раздела Database (урок 24) решаются на SQL.

## Безопасность

Платформа выполняет **твой** код на твоём компьютере (как `go run`). Поэтому:
- сервер слушает только `127.0.0.1` (другие адреса запрещены);
- запросы с чужих сайтов блокируются: проверяется `Host`, а изменяющие запросы требуют служебный заголовок;
- код запускается во временных папках с лимитом времени (10 с запуск, 20 с тесты) и вывода (64 КБ).
Не публикуй порт наружу. Единственное исключение — свой сервер (см. ниже): там платформа слушает не только localhost, **только** если задан `GOLEARN_PASSWORD` (≥12 символов), и вход по паролю обязателен; без пароля сервер не стартует.

### Проверка контента

```bash
go test -run TestContent -v            # все эталонные решения проходят тесты, шаблоны — нет, все ▶-примеры запускаются
VERIFY=l15 go test -run TestContent    # только уроки/задания с префиксом l15
```

### Как добавить своё задание

Создай `content/tasks/l05-my-task.md` (префикс — id урока):

````text
---
title: Название
level: easy | medium | hard
---
@@ statement
Условие в markdown.
@@ starter
package solution
func F() int { return 0 }
@@ tests
package solution
import "testing"
func TestF(t *testing.T) { if F() != 1 { t.Fatal("...") } }
@@ solution
package solution
func F() int { return 1 }
@@ hint
Необязательная подсказка.
````

Запусти `go test -run TestContent` — проверка убедится, что решение проходит, а шаблон нет.

Формат урока: front matter (`id`, `week`, `day`, `minutes`, `title`, `goals`, повторяемые строки `lc: slug | Название | Easy | подсказка`) и markdown. Блок ```` ```go run ```` — редактируемый запускаемый пример (нужен полный `package main`).

## Синхронизация прогресса между устройствами (git)

Прогресс (`progress.json`: пройденные уроки, решённые задания, черновики кода, LeetCode, карточки) лежит **в репозитории**, поэтому синхронизируется через git.

```bash
git clone https://github.com/RoomiestThunder/golang-learn.git && cd golang-learn
./run.sh        # pull → запуск платформы → после Ctrl+C: commit + push прогресса
```

Правила, чтобы не терять данные:
- Запускай через `./run.sh` (он сам подтягивает и отправляет прогресс), либо вручную: `git pull --rebase` перед работой и `git add progress.json && git commit -m progress && git push` после.
- Не работай на двух устройствах одновременно без синхронизации между сессиями.
- Если при `pull` возник конфликт в `progress.json` — это обычный JSON с отсортированными ключами: оставь обе версии записей (решённые задачи и уроки объединяются), счётчики в `days` бери бо́льшие, затем `git add progress.json && git rebase --continue`.
- Репозиторий публичный: в `progress.json` видны твои черновики решений, ник LeetCode и даты занятий. Если это нежелательно — сделай репозиторий приватным (Settings → Danger Zone → Change visibility).

## Запуск в облаке: GitHub Codespaces

Платформа запускает Go-код на сервере, поэтому статический GitHub Pages не подходит — вместо него есть Codespaces (облачное окружение GitHub, настроено в `.devcontainer/`):

1. На странице репозитория: **Code → Codespaces → Create codespace on main**.
2. Окружение само поставит Go, выполнит `./run.sh` (подтянет прогресс и запустит платформу) и откроет вкладку с приложением; если не открылась — вкладка **Ports → Go Learn (8088)**.
3. После остановки (`Ctrl+C` в терминале) `run.sh` сам закоммитит и отправит `progress.json`, поэтому прогресс общий с локальным компьютером.

Порт в Codespaces приватный — приложение видишь только ты. Для запросов через проброс портов сервер автоматически разрешает хост `<codespace>-8088.<домен>`; дополнительные хосты можно разрешить переменной `GOLEARN_ALLOWED_HOSTS=host1,host2`. Остановленный codespace не расходует часы бесплатного лимита; на бесплатном тарифе есть ежемесячный лимит часов.

## Свой сервер: Google Cloud Run

Платформа открывается в браузере с любого устройства по адресу вида `https://golearn-….run.app` под твоим паролем. Нужен проект Google Cloud с подключённым платёжным аккаунтом (Cloud Run без него не включается); для личного использования обычно хватает бесплатных квот — актуальные тарифы смотри у Google.

1. В [консоли Google Cloud](https://console.cloud.google.com/) открой **Cloud Shell** (кнопка `>_` справа вверху).
2. Выполни:
   ```bash
   git clone https://github.com/RoomiestThunder/golang-learn.git && cd golang-learn
   gcloud config set project <ID_ПРОЕКТА>
   bash deploy/cloudrun.sh
   ```
3. Скрипт включит API, создаст бакет для прогресса, отдельный сервис-аккаунт с минимальными правами и секрет с паролем, соберёт образ и выложит сервис. В конце он **один раз** покажет пароль и адрес — сохрани пароль. Свой пароль можно задать так: `GOLEARN_PASSWORD=... bash deploy/cloudrun.sh` (≥12 символов).
4. Открой адрес, введи пароль — сессия на этом устройстве хранится 30 дней.

Как это устроено и что учесть:
- **Прогресс** лежит в бакете Cloud Storage (`<проект>-golearn-data`, файл `progress.json`) и не зависит от перезапусков. Первый раз он берётся из `progress.json` репозитория. С git-синхронизацией (`run.sh`) серверный прогресс **не связан** — считай сервер основным местом занятий.
- Сервис настроен на **один экземпляр** (`--max-instances 1`) — это обязательно, иначе два экземпляра перезаписывали бы прогресс друг друга.
- Без нагрузки сервис засыпает; первое открытие после паузы занимает несколько секунд. Чтобы не засыпал: `gcloud run services update golearn --region europe-west1 --min-instances 1` (это платно).
- **Обновление** курса: `git pull && bash deploy/cloudrun.sh` — пароль и прогресс сохраняются. Сменить пароль: `printf %s 'новый-пароль' | gcloud secrets versions add golearn-password --data-file=-`, затем повторить деплой (старые сессии станут недействительны).
- Забыл пароль: `gcloud secrets versions access latest --secret golearn-password`. Резервная копия прогресса: `gcloud storage cp gs://<проект>-golearn-data/progress.json .`
- Платформа **исполняет произвольный Go-код**. Защита — длинный пароль, пауза после неверной попытки (≈1 попытка в секунду на весь сервер), HTTPS от Cloud Run и изоляция контейнера; внутри он работает под обычным пользователем с сервис-аккаунтом без прав на остальной проект. Не отправляй пароль никому и не снимай защиту.
- Регион по умолчанию `europe-west1`; другой: `REGION=europe-west4 bash deploy/cloudrun.sh`.

### Альтернатива: виртуальная машина (VPS) с Docker

На любой Linux-VM с Docker (Google Compute Engine, Oracle, Hetzner и т. п.; рекомендуется ≥2 ГБ ОЗУ, открытые порты 80 и 443):

```bash
git clone https://github.com/RoomiestThunder/golang-learn.git && cd golang-learn
cp .env.example .env && nano .env       # DOMAIN и GOLEARN_PASSWORD
docker compose up -d --build
```

Caddy сам получит HTTPS-сертификат для `DOMAIN` (без своего домена подойдёт `<IP-через-дефисы>.sslip.io`). Прогресс — в Docker-томе `data`; обновление: `git pull && docker compose up -d --build`.
