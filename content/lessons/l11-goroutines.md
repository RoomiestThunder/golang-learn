## Горутина — легковесный поток выполнения

`go f(x)` запускает функцию **конкурентно**. Горутина — не поток ОС: стартует со стеком ~2 КБ (растёт динамически), создаётся за ~микросекунды, runtime мультиплексирует миллионы горутин на небольшое число ОС-потоков (модель **GMP**, подробно в неделе 6).

> [!NOTE] **Конкурентность ≠ параллелизм.** Конкурентность — структура программы из независимо выполняющихся частей. Параллелизм — их одновременное исполнение на разных ядрах. Go даёт первое, а второе получается, если ядер больше одного (`GOMAXPROCS`, по умолчанию = число ядер).

```go run
package main

import (
	"fmt"
	"time"
)

func say(s string) {
	for i := 0; i < 3; i++ {
		fmt.Println(s, i)
		time.Sleep(10 * time.Millisecond)
	}
}

func main() {
	go say("горутина") // запустили и пошли дальше
	say("main")
	// когда main возвращается, ВСЕ горутины убиваются, не доработав!
	time.Sleep(50 * time.Millisecond) // плохой способ ожидания, только для демонстрации
}
```

Ключевое правило: **программа завершается, когда завершается `main`**, независимо от остальных горутин. Поэтому нужны примитивы ожидания.

## sync.WaitGroup

```go run
package main

import (
	"fmt"
	"sync"
)

func main() {
	var wg sync.WaitGroup
	results := make([]int, 5) // каждая горутина пишет в СВОЙ элемент — гонки нет

	for i := range 5 {
		wg.Add(1) // ВАЖНО: Add до запуска горутины, а не внутри неё
		go func() {
			defer wg.Done()
			results[i] = i * i
		}()
	}

	wg.Wait() // блокируемся, пока счётчик не станет 0
	fmt.Println(results)
}
```

Правила `WaitGroup`: `Add(n)` вызывай **до** `go`; `Done()` — через `defer`; не копируй `WaitGroup` (передавай указатель). В Go 1.25 добавлен удобный `wg.Go(func(){...})`, который сам делает `Add/Done`.

## Гонка данных (data race)

Когда две горутины обращаются к одной переменной **без синхронизации** и хотя бы одна пишет — это гонка. Поведение не определено: потерянные обновления, битые данные.

```go run
package main

import (
	"fmt"
	"sync"
	"sync/atomic"
)

func main() {
	var wg sync.WaitGroup

	// 1) гонка: counter++ — это чтение, сложение и запись; потоки затирают друг друга
	racy := 0
	for i := 0; i < 1000; i++ {
		wg.Add(1)
		go func() { defer wg.Done(); racy++ }()
	}
	wg.Wait()

	// 2) чиним мьютексом
	var mu sync.Mutex
	safe := 0
	for i := 0; i < 1000; i++ {
		wg.Add(1)
		go func() {
			defer wg.Done()
			mu.Lock()
			safe++
			mu.Unlock()
		}()
	}
	wg.Wait()

	// 3) или атомиком — быстрее для простых счётчиков
	var atom atomic.Int64
	for i := 0; i < 1000; i++ {
		wg.Add(1)
		go func() { defer wg.Done(); atom.Add(1) }()
	}
	wg.Wait()

	fmt.Println("racy (может быть < 1000):", racy > 0, "| mutex:", safe, "| atomic:", atom.Load())
}
```

**Детектор гонок**: `go run -race main.go`, `go test -race ./...` — обязателен в CI. Он находит гонки, которые реально произошли во время запуска (не доказывает отсутствие). Требует cgo, замедляет программу в 5–10 раз.

## Передача данных в горутину

Благодаря семантике Go 1.22 замыкание на `i` безопасно. Но всё равно помни: захваченная переменная **общая**. Если нужно зафиксировать значение или работаешь со старым кодом — передавай аргументом:

```go
for _, url := range urls {
	go func(u string) { fetch(u) }(url) // u — копия на момент запуска
}
```

## Утечки горутин

Горутина, которая никогда не завершится (ждёт канал, который никто не закроет), **живёт вечно** вместе со своим стеком и всеми ссылками. Это самая частая проблема конкурентного Go:

```go
func leak() {
	ch := make(chan int)
	go func() { ch <- 1 }() // никто не читает — горутина зависла навсегда
}
```

Правила: у каждой горутины должен быть **понятный способ остановиться** (закрытие канала, `context`); тот, кто запускает горутину, отвечает за её остановку; диагностика — `runtime.NumGoroutine()`, профиль `goroutine` в pprof, библиотека `goleak` в тестах.

## Паника в горутине

Необработанная паника в любой горутине **завершает весь процесс**. В долгоживущих горутинах (воркеры, обработчики) ставь `defer recover()` и логирование.

## Полезные функции runtime

```go
runtime.NumCPU()        // число логических ядер
runtime.GOMAXPROCS(0)   // текущее значение (0 = не менять)
runtime.NumGoroutine()  // сколько горутин живо
runtime.Gosched()       // уступить процессор другим горутинам
```

## Проверь себя

<details><summary>Что произойдёт, если <code>main</code> завершится раньше горутин?</summary>Программа завершится, незавершённые горутины будут остановлены без выполнения defer.</details>

<details><summary>Почему <code>wg.Add(1)</code> нужно вызывать до <code>go</code>?</summary>Иначе <code>Wait()</code> может увидеть нулевой счётчик и вернуться раньше, чем горутина успеет сделать <code>Add</code>.</details>

<details><summary>Как найти гонку данных?</summary>Запустить с флагом <code>-race</code> (<code>go test -race</code>).</details>

<details><summary>Что такое утечка горутины и как её избежать?</summary>Горутина, которая навсегда заблокирована; нужно гарантировать выход — закрытием канала или отменой контекста.</details>
