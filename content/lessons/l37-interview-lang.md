Ниже — задачи «что выведет программа?». Сначала **предскажи** вывод, запиши ответ, потом запусти (▶) и сравни; разбор — под спойлером. Это самый быстрый способ проверить, что ты понимаешь язык, а не помнишь синтаксис.

## Блок 1: defer, замыкания, срезы

```go run
package main

import "fmt"

func a() (r int) {
	defer func() { r *= 2 }()
	return 5
}

func b() int {
	x := 1
	defer fmt.Println("b defer x =", x)
	x = 100
	return x
}

func main() {
	fmt.Println(a(), b())

	for i := 0; i < 3; i++ {
		defer func() { fmt.Print("d", i, " ") }()
	}

	s := []int{1, 2, 3, 4, 5}
	t := s[1:3]
	t = append(t, 99)
	fmt.Println(s, t, len(t), cap(t))

	u := make([]int, 3, 10)
	v := append(u, 1)
	w := append(u, 2)
	fmt.Println(v[3], w[3])

	arr := [3]int{1, 2, 3}
	brr := arr
	brr[0] = 100
	fmt.Println(arr, brr)
}
```

<details><summary>Ответ и разбор</summary>

1. `a()` → `10`: defer меняет именованный результат после `return 5`.
2. `b()`: сначала печатается «b defer x = 1» (аргумент вычислен при `defer`), результат `100`; в `Println` вызовы идут слева направо, поэтому строка «b defer…» выводится ДО итоговой строки `10 100`.
3. Три отложенные функции печатают `d2 d1 d0` — LIFO; с Go 1.22 у каждой итерации своя `i`.
4. `s = [1 2 3 99 5]`, `t = [2 3 99]`, `len 3`, `cap 4` — append поместился в ёмкость и затёр `s[3]`.
5. `v[3]` и `w[3]` равны `2`: оба слайса делят один массив.
6. Массивы копируются: `[1 2 3] [100 2 3]`.
</details>

## Блок 2: map, указатели, range

```go run
package main

import "fmt"

type P struct{ N int }

func main() {
	ps := []P{{1}, {2}, {3}}
	for _, p := range ps {
		p.N *= 10 // меняем копию
	}
	fmt.Println(ps)
	for i := range ps {
		ps[i].N *= 10
	}
	fmt.Println(ps)

	m := map[string]P{"a": {1}}
	// m["a"].N = 5   // не компилируется: элемент map не адресуем
	p := m["a"]
	p.N = 5
	m["a"] = p
	fmt.Println(m)

	pm := map[string]*P{"a": {1}}
	pm["a"].N = 7 // через указатель можно
	fmt.Println(pm["a"].N)

	var nilMap map[string]int
	fmt.Println(nilMap["x"], len(nilMap)) // чтение из nil-map безопасно
	// nilMap["x"] = 1                    // panic: assignment to entry in nil map

	var ptrs []*int
	for i := 0; i < 3; i++ {
		ptrs = append(ptrs, &i) // Go 1.22+: у каждой итерации свой i
	}
	fmt.Println(*ptrs[0], *ptrs[1], *ptrs[2])
}
```

<details><summary>Ответ и разбор</summary>

1. Первый цикл меняет копии: `[{1} {2} {3}]`; второй — реальные элементы: `[{10} {20} {30}]`.
2. `map[a:{5}]` — элемент map нужно достать, изменить и записать обратно (или хранить указатели).
3. `7`.
4. `0 0`.
5. `0 1 2` в Go ≥ 1.22 (до 1.22 было бы `3 3 3`).
</details>

## Блок 3: интерфейсы, строки, числа

```go run
package main

import (
	"errors"
	"fmt"
)

type MyErr struct{}

func (*MyErr) Error() string { return "my" }

func get(fail bool) error {
	var e *MyErr
	if fail {
		e = &MyErr{}
	}
	return e
}

type Animal interface{ Sound() string }
type Dog struct{ name string }

func (d *Dog) Sound() string { return d.name + " гав" }

func main() {
	fmt.Println(get(false) == nil, get(true) == nil)

	var a Animal = &Dog{"Рекс"}
	fmt.Println(a.Sound())
	// var b Animal = Dog{"X"}  // не компилируется: метод Sound на *Dog

	s := "привет"
	fmt.Println(len(s), len([]rune(s)), s[0], string(s[0:2]))

	var u8 uint8 = 255
	u8++
	var i8 int8 = 127
	i8++
	fmt.Println(u8, i8)

	const big = 1 << 40 // untyped константа — вмещается в int64
	fmt.Println(big/1024, 7/2, -7/2, 7%3, -7%3)

	x := 0.1
	y := 0.2
	fmt.Println(x+y == 0.3, x+y)

	e1 := errors.New("a")
	e2 := errors.New("a")
	fmt.Println(e1 == e2, e1.Error() == e2.Error())
}
```

<details><summary>Ответ и разбор</summary>

1. `false true` — typed nil внутри интерфейса не равен nil (поэтому `get(false) == nil` ложно).
2. `Рекс гав`.
3. `12 6 208 п` — `len` в байтах; `s[0]` — первый байт (0xD0 = 208); срез первых двух байт — буква «п».
4. `0 -128` — переполнение целых заворачивается.
5. `1073741824 3 -3 1 -1` — деление усекает к нулю, остаток имеет знак делимого.
6. `false 0.30000000000000004` — вещественные числа хранятся приближённо; `+` для переменных идёт в рантайме (для констант точная арифметика).
7. `false true` — разные значения `*errorString`; сравнивайте через `errors.Is`.
</details>

## Блок 4: горутины и каналы

```go run
package main

import (
	"fmt"
	"sync"
)

func main() {
	ch := make(chan int, 2)
	ch <- 1
	ch <- 2
	close(ch)
	for v := range ch {
		fmt.Print(v, " ")
	}
	v, ok := <-ch
	fmt.Println(v, ok)

	var wg sync.WaitGroup
	var mu sync.Mutex
	total := 0
	for i := 1; i <= 100; i++ {
		wg.Add(1)
		go func() {
			defer wg.Done()
			mu.Lock()
			total += i
			mu.Unlock()
		}()
	}
	wg.Wait()
	fmt.Println(total)

	done := make(chan struct{})
	data := make(chan string)
	go func() {
		defer close(done)
		for s := range data {
			fmt.Print(s, " ")
		}
	}()
	for _, w := range []string{"a", "b", "c"} {
		data <- w
	}
	close(data)
	<-done
	fmt.Println()
}
```

<details><summary>Ответ и разбор</summary>

1. `1 2 0 false` — из закрытого канала сначала читается остаток буфера, потом нулевые значения с `ok == false`.
2. `5050` — мьютекс защищает общий счётчик; благодаря семантике Go 1.22 каждая горутина получает своё `i`.
3. `a b c` — небуферизованный канал синхронизирует отправку и приём; `close` завершает `range`; `done` гарантирует, что горутина допечатала.
</details>

## Самые частые вопросы по языку (и краткие ответы)

**Типы и память**
- *Чем slice отличается от array?* Array — значение фиксированной длины; slice — дескриптор (ptr, len, cap) над массивом.
- *Что происходит при `append` при нехватке cap?* Выделяется новый массив (≈×2 для небольших), данные копируются, возвращается новый слайс; старые ссылки указывают на старый массив.
- *Как работает `map` и безопасна ли она?* Хэш-таблица; порядок итерации случаен; конкурентная запись — fatal error; нужен Mutex/sync.Map.
- *Что такое zero value?* Значение по умолчанию типа: 0, "", nil, false; хороший тип делает его полезным.
- *Стек или куча?* Решает компилятор (escape analysis); `-gcflags=-m` показывает решения.
- *Почему строки неизменяемы и что такое руна?* Для безопасного разделения памяти; руна — `int32` кодовая точка Unicode.

**Функции и методы**
- *Value vs pointer receiver?* Pointer — если меняем состояние, структура большая или содержит мьютекс; в остальном value; не смешивать.
- *Что делает defer, порядок?* Откладывает вызов до выхода из функции; LIFO; аргументы вычисляются сразу.
- *panic/recover?* recover работает только в defer; для невосстановимых ошибок.
- *Замыкания и переменная цикла?* Замыкание захватывает переменную по ссылке; с 1.22 у итерации своя копия.

**Интерфейсы и ошибки**
- *Как реализуется интерфейс?* Неявно набором методов.
- *Устройство интерфейса, nil-ловушка?* (тип, значение); typed nil ≠ nil.
- *errors.Is / As / %w?* Сравнение по цепочке / извлечение типа / обёртка.
- *Когда any и когда дженерики?* Дженерики — для типобезопасных контейнеров и алгоритмов; any — для действительно разнородных данных.
- *«Принимай интерфейсы, возвращай структуры» — почему?*

**Прочее**
- *Что такое `init()`, порядок инициализации пакетов?*
- *Как устроены модули, что в go.sum?*
- *Что такое `go vet`, `-race`, чем отличается от тестов?*
- *Как сравнивать структуры, какие типы можно использовать как ключ map?*
- *Что такое embedding и чем отличается от наследования?*
- *Как работает `select`, что если готовы несколько case?*

## Как отвечать на собеседовании

1. Сначала **короткий точный ответ**, затем «глубина» (устройство, пример, подводный камень).
2. Если не знаешь — рассуждай вслух от известного, не угадывай молча.
3. Приводи **примеры из практики** («у нас была утечка горутин из-за…»).
4. Уточняй вопрос, проговаривай допущения.
5. Не бойся сказать «не уверен, проверил бы в документации/бенчмарком».
