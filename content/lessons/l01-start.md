## Что такое Go и зачем он нужен

Go (Golang) — компилируемый статически типизированный язык с автоматической сборкой мусора, созданный в Google (Pike, Thompson, Griesemer). Ставка сделана на **простоту**, **быструю компиляцию** и **встроенную конкурентность**.

| Что | Как в Go |
|---|---|
| Компиляция | В один статический бинарь без зависимостей (легко деплоить, идеален для Docker) |
| Память | GC, указатели есть, арифметики указателей нет |
| Конкурентность | Горутины + каналы встроены в язык и runtime |
| Полиморфизм | Интерфейсы (структурная типизация), без наследования |
| Ошибки | Значения (`error`), не исключения |
| Обобщения | С Go 1.18 (дженерики) |
| Формат кода | Один: `gofmt` решает все споры о стиле |

Типичные области: бэкенд/микросервисы, инфраструктура (Docker, Kubernetes, Terraform написаны на Go), CLI-утилиты, сетевые сервисы.

> [!INTERVIEW] «Почему Go, а не Java/Python?» — быстрый старт и малое потребление памяти, простая модель конкурентности, один бинарь, предсказуемая производительность, низкий порог входа в чужой код.

## Toolchain: команды, которые ты будешь использовать каждый день

```bash
go version              # версия компилятора
go run main.go          # скомпилировать и сразу запустить (бинарь во временной папке)
go build -o app ./cmd/app   # собрать бинарь
go test ./...           # тесты всех пакетов; -v подробно, -race детектор гонок, -cover покрытие
go fmt ./...            # отформатировать (gofmt -w)
go vet ./...            # статический анализ типичных ошибок
go mod init example.com/app # создать модуль (go.mod)
go mod tidy             # подтянуть недостающие и убрать лишние зависимости
go get github.com/x/y@v1.2.3 # добавить зависимость
go doc fmt.Printf       # документация прямо в терминале
go env GOPATH GOROOT    # окружение
```

**Модуль** — единица версионирования, описывается файлом `go.mod`: путь модуля, версия Go, зависимости. **Пакет** — папка с `.go`-файлами с одинаковым `package`. Один каталог = один пакет.

## Первая программа

```go run
package main

import "fmt"

func main() {
	fmt.Println("Привет, Go!")
}
```

Разбор:

- `package main` — исполняемая программа; точка входа — `func main()` в пакете `main`.
- `import` — подключение пакетов. **Неиспользуемый импорт или переменная — ошибка компиляции.** Это сделано специально.
- Фигурная скобка `{` обязана быть на той же строке (иначе автоматическая вставка `;`).

Попробуй: сломай код (убери импорт `fmt`, но оставь вызов), нажми ▶ и прочитай ошибку компилятора.

## Видимость: регистр первой буквы

В Go нет `public/private`. Если имя начинается с **заглавной** буквы — оно экспортируется из пакета (`fmt.Println`), со строчной — видно только внутри пакета.

## Пакет fmt: форматированный вывод

```go run
package main

import "fmt"

type Point struct {
	X, Y int
}

func main() {
	p := Point{3, 4}
	name := "Gopher"
	pi := 3.14159265

	fmt.Println("Println добавляет пробелы и \\n:", name, 42)
	fmt.Printf("%v | %+v | %#v | %T\n", p, p, p, p) // значение, с полями, как в коде Go, тип
	fmt.Printf("строка %s, в кавычках %q\n", name, name)
	fmt.Printf("целое %d, hex %x, бинарное %b, символ %c, Unicode %U\n", 255, 255, 5, 'G', 'G')
	fmt.Printf("float %f | %.2f | %8.3f| %e\n", pi, pi, pi, pi)
	fmt.Printf("ширина [%5d] [%-5d] [%05d]\n", 42, 42, 42)
	fmt.Printf("bool %t, указатель на тип %T, %%\n", true, &p)

	s := fmt.Sprintf("Sprintf возвращает строку: %d-%d", p.X, p.Y) // не печатает, а возвращает
	fmt.Println(s)
}
```

Главные «глаголы»: `%v` (универсальный), `%+v` (с именами полей — удобно для отладки), `%#v` (синтаксис Go), `%T` (тип), `%d`, `%s`, `%q`, `%f`, `%t`, `%p`, `%x`. Семейство функций: `Print/Println/Printf` (в stdout), `Sprint*` (в строку), `Fprint*` (в `io.Writer`), `Errorf` (в ошибку).

> [!WARNING] `go vet` ловит несовпадение глаголов и аргументов (`Printf("%d", "str")`). Запускай его — и `go test` делает это автоматически.

## Аргументы командной строки и ввод

```go
package main

import (
	"bufio"
	"fmt"
	"os"
)

func main() {
	fmt.Println("аргументы:", os.Args[1:]) // os.Args[0] — имя программы

	sc := bufio.NewScanner(os.Stdin) // чтение построчно
	for sc.Scan() {
		fmt.Println("прочитано:", sc.Text())
	}
}
```

(В песочнице этот пример не запускается — нет stdin; запускай локально: `echo hi | go run main.go a b`.)

## init() и порядок инициализации

Перед `main` выполняются: инициализация пакетных переменных (в порядке зависимостей), затем все функции `init()` (их может быть несколько в пакете). Импортируемые пакеты инициализируются раньше. Используй `init` редко — скрытая магия мешает тестированию.

```go run
package main

import "fmt"

var a = b + 1 // инициализация идёт по зависимостям, а не по порядку записи
var b = f()

func f() int { fmt.Println("инициализация b"); return 10 }

func init() { fmt.Println("init, a =", a) }

func main() { fmt.Println("main") }
```

## Документация и комментарии

Комментарий прямо над объявлением, начинающийся с имени, становится документацией (`go doc`, pkg.go.dev):

```go
// Greet возвращает приветствие для name.
func Greet(name string) string { ... }
```

## Проверь себя

<details><summary>Что произойдёт, если объявить переменную и не использовать её?</summary>Ошибка компиляции «declared and not used». Исключение — пустой идентификатор `_` и пакетные (глобальные) переменные.</details>

<details><summary>Чем <code>go run</code> отличается от <code>go build</code>?</summary><code>go run</code> компилирует во временную папку и запускает, бинарь не сохраняется; <code>go build</code> оставляет исполняемый файл.</details>

<details><summary>Как сделать функцию доступной из другого пакета?</summary>Назвать её с заглавной буквы.</details>

<details><summary>Что такое модуль и чем он отличается от пакета?</summary>Модуль — корень проекта с <code>go.mod</code> (версионируется целиком), пакет — одна папка с исходниками внутри модуля.</details>
