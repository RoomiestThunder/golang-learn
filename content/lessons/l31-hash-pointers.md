## Как решать алгоритмические задачи (и не паниковать)

Алгоритмические секции — часть собеседований, но 80% задач сводятся к ~15 шаблонам. План на любую задачу:

1. **Переформулируй** условие своими словами, уточни ограничения (размер входа, отрицательные числа, дубликаты, пустой вход).
2. Приведи **пример** и крайние случаи (пусто, один элемент, все равны).
3. Опиши **наивное решение** и его сложность. Скажи вслух — это уже не ноль.
4. Найди **узкое место** и шаблон, который его убирает (хэш-таблица, два указателя, сортировка, окно, куча…).
5. Напиши код, затем **прогони на примере** руками.
6. Назови итоговую **сложность по времени и памяти**.

Ограничения подсказывают сложность: `n ≤ 10⁵` → нужно `O(n log n)` или лучше; `n ≤ 20` → перебор `2ⁿ`; `n ≤ 500` → допустимо `O(n³)`.

## Big-O: шпаргалка

| Сложность | Пример | n = 10⁶ |
|---|---|---|
| O(1) | доступ по индексу, операция с map | мгновенно |
| O(log n) | бинарный поиск, операции кучи | ~20 шагов |
| O(n) | один проход | ~10⁶ |
| O(n log n) | сортировка | ~2·10⁷ |
| O(n²) | двойной цикл | 10¹² — не успеть |
| O(2ⁿ), O(n!) | полный перебор | только для малых n |

Сложность по **памяти** тоже считается. Амортизированная: `append` — O(1) амортизированно, хотя иногда копирует весь массив.

Операции Go: `map` — O(1) среднее; `append` — O(1) амортизированно; `s[i:j]` — O(1) (без копирования); `copy`, `slices.Sort` — O(n)/O(n log n); `string +=` в цикле — O(n²); конкатенация/`[]byte(s)` копируют — O(n); `len` — O(1).

## Шаблон 1: хэш-таблица

**Идея:** заменить вложенный поиск на запоминание уже виденного → O(n²) → O(n).

```go run
package main

import (
	"fmt"
	"sort"
	"strings"
)

// Two Sum: для каждого x ищем complement = target - x среди уже виденных
func twoSum(nums []int, target int) []int {
	seen := make(map[int]int, len(nums)) // значение → индекс
	for i, x := range nums {
		if j, ok := seen[target-x]; ok {
			return []int{j, i}
		}
		seen[x] = i
	}
	return nil
}

// Group Anagrams: ключ — каноническая форма. Массив [26]int сравним, значит годится как ключ map!
func groupAnagrams(words []string) [][]string {
	groups := map[[26]int][]string{}
	for _, w := range words {
		var key [26]int
		for _, r := range w {
			key[r-'a']++
		}
		groups[key] = append(groups[key], w)
	}
	out := make([][]string, 0, len(groups))
	for _, g := range groups {
		out = append(out, g)
	}
	sort.Slice(out, func(i, j int) bool { return strings.Join(out[i], "") < strings.Join(out[j], "") })
	return out
}

// Подсчёт подмассивов с суммой k: префиксные суммы + map частот
func subarraySum(nums []int, k int) int {
	count, prefix := 0, 0
	freq := map[int]int{0: 1}
	for _, x := range nums {
		prefix += x
		count += freq[prefix-k] // сколько раз встречалась нужная «левая» префиксная сумма
		freq[prefix]++
	}
	return count
}

func main() {
	fmt.Println(twoSum([]int{2, 7, 11, 15}, 9))
	fmt.Println(groupAnagrams([]string{"eat", "tea", "tan", "ate", "nat", "bat"}))
	fmt.Println(subarraySum([]int{1, 2, 3, -3, 3}, 3))
}
```

Типовые применения: частоты (`map[T]int`), множества (`map[T]struct{}`), «видел ли я это?», каноническая форма для группировки (отсортированная строка, `[26]int`), индексы значений, префиксные суммы с хэшем.

**Go-детали:** ключом может быть массив, структура из сравнимых полей, `string`, но не слайс. Для `byte`/`rune`-алфавита из 26 букв быстрее массив `[26]int`, чем map. Порядок обхода map случаен — для детерминированного результата сортируй.

## Шаблон 2: два указателя

**Идея:** два индекса двигаются по структуре, избавляя от вложенного цикла.

### 2а. С двух концов (отсортированный массив/строка)

```go run
package main

import "fmt"

// пара с суммой target в ОТСОРТИРОВАННОМ массиве за O(n) и O(1) памяти
func twoSumSorted(a []int, target int) (int, int, bool) {
	l, r := 0, len(a)-1
	for l < r {
		switch s := a[l] + a[r]; {
		case s == target:
			return l, r, true
		case s < target:
			l++ // нужна сумма больше → двигаем левый вперёд
		default:
			r--
		}
	}
	return 0, 0, false
}

func main() {
	fmt.Println(twoSumSorted([]int{1, 3, 4, 6, 8, 11}, 10))
}
```

Применения: палиндром, контейнер с водой, квадраты отсортированного массива, 3Sum/4Sum (фиксируем первый + два указателя).

### 2б. Читающий и пишущий (одно направление)

Фильтрация/сжатие «на месте»: `read` проходит по всему массиву, `write` отмечает позицию записи.

```go
func removeDuplicates(nums []int) int { // отсортированный массив
	if len(nums) == 0 { return 0 }
	w := 1
	for r := 1; r < len(nums); r++ {
		if nums[r] != nums[w-1] {
			nums[w] = nums[r]
			w++
		}
	}
	return w
}
```

(Тот же приём — в задании про `FilterInPlace`.) Применения: Move Zeroes, Remove Element, Remove Duplicates, partition.

### 2в. Быстрый и медленный

Линейные структуры: середина списка, цикл (Флойд), n-й с конца (быстрый стартует на n шагов раньше). Подробнее — в уроке про списки.

## Сортировка как инструмент

Если порядок не важен, **сортировка за O(n log n)** часто превращает задачу в проход с двумя указателями (3Sum, объединение интервалов, ближайшие пары). Не забывай `slices.SortFunc`/`sort.Slice` с компаратором.

## Типичные ошибки

- Забыть про дубликаты в 3Sum (пропускай одинаковые на каждом уровне: `for i > 0 && nums[i] == nums[i-1]`).
- Переполнение `int` при суммах (в Go `int` 64-бит на 64-битных платформах — обычно хватает; LeetCode: платформа 64-бит).
- Изменение map во время итерации (допустимо удалять, но результат при добавлении непредсказуем).
- Путаница индекса и значения в `range`.

## Проверь себя

<details><summary>Почему Two Sum через map лучше, чем двойной цикл?</summary>Поиск дополнения в map O(1), поэтому весь алгоритм O(n) времени (за счёт O(n) памяти) вместо O(n²).</details>

<details><summary>Можно ли использовать массив как ключ map? Слайс?</summary>Массив — да (сравним, если сравним элемент), слайс — нет.</details>

<details><summary>Когда применим метод двух указателей навстречу?</summary>Когда данные отсортированы (или есть монотонность), и по текущему состоянию понятно, какой указатель двигать.</details>
